What it does

Password storage that keeps up with its own policy

Each card opens its section on the features page. hsh runs on Linux, macOS and Windows, from the command line, and with the AWS-LC FIPS module.

01

One policy, four algorithms

Argon2id, bcrypt, scrypt and PBKDF2 behind one Policy. New hashes use its algorithm; any of the four verifies.

  • Argon2id: 19,456 KiB of memory, 2 passes, 1 lane. Memory-hard, the recommended choice for new systems.
  • bcrypt at cost 10 with a 72-byte limit; scrypt at N = 217, r = 8, p = 1.
  • PBKDF2: HMAC-SHA-256 with 600,000 iterations. The only one of the four with FIPS-validated implementations.

02

Rehash on login

When a stored hash is weaker than the policy, a successful verify returns a fresh hash to save in its place.

How upgrades happen

03

A pepper with key rotation

An HMAC-SHA-256 pepper with numbered keys, so a stolen database alone cannot be cracked offline.

How the pepper works

04

FIPS 140-3 mode

A FIPS policy hashes only with PBKDF2 through the AWS-LC FIPS module, and refuses to hash at all in a build that cannot.

What the mode guarantees

05

Safety rails

bcrypt input over 72 bytes is rejected, not truncated; comparisons are constant time; secrets are wiped from memory.

A command-line tool

hsh hashes, verifies, rehashes and inspects from the shell, and calibrates the cost to your hardware.

Install

Hash, verify and upgrade in one call

Hash with a policy, then verify with the same policy: a hash that has fallen behind comes back upgraded. The library needs Rust 1.85 or newer. Add it with cargo add hsh, or install the command with cargo install hsh-cli.

src/main.rs
use hsh::{api, Outcome, Policy};

fn main() -> Result<(), hsh::Error> {
    let policy = Policy::owasp_minimum_2025();
    let stored = api::hash(&policy, "correct horse")?;

    match api::verify_and_upgrade(&policy, "correct horse", &stored)? {
        Outcome::Valid { rehashed: Some(new) } => { /* save new */ }
        Outcome::Valid { rehashed: None } => { /* signed in */ }
        Outcome::Invalid => { /* deny */ }
    }
    Ok(())
}

Security

Fails closed, and says so

hsh refuses rather than degrades: no silent truncation, no silent fallback from a FIPS policy, no peppered hash accepted without its key.

hsh is at 0.0.x and has not had a third-party audit. The security page lists what is checked, what is a stub, and what is not promised.
